# 웹 결제(포트원) 설정 가이드

작성: 2026-10-22 · 대상: 웹 브라우저 정기결제(카드·카카오페이, 나중에 네이버페이)

- 코드는 **기본으로 꺼져 있습니다**(`BILLING_PG_ENABLED`). 키를 넣고 스위치를 켜기 전에는 운영에 바뀌는 것이 없습니다.
- 결제는 **웹 브라우저에서만** 받습니다. 앱(MaeumApp) 안에서는 결제 화면·가격·링크가 보이지 않고, 서버도 앱에서 온 결제 요청을 거절합니다. 해지·환불은 우리 앱이 틀림없는 요청만 거절합니다(다른 앱의 인앱 브라우저를 오판해 해지를 막지 않게).
- 결제는 **보호자 계정만** 합니다(10-22 검토 반영 — 하루 대화 한도는 어르신 계정에만 있어, 일반인·어르신·의사 계정은 결제할 수 없습니다).
- 위급 감지·119 안내·보호자 위급 알림은 결제와 관계없이 늘 무료입니다. 결제가 실패하거나 끝나도 막히지 않습니다.
- 앱 안 Play 결제(Play Console 상품·RTDN·라이선스 테스터·`BILLING_ENFORCE`)는 `docs/playstore/구독결제_설정과_재심사.md`에서 다룹니다. 이 문서는 웹 결제만 다룹니다. 두 결제는 같은 구독 표를 쓰고, 어르신에게 이미 살아 있는 이용권(Play 포함)이 있으면 웹 결제를 새로 받지 않습니다.
- 비밀값(API Secret·웹훅 시크릿·CRON_SECRET)은 **Vercel 환경 변수에만** 넣습니다. 코드, 채팅, 이 문서에 붙여 넣지 마세요.
- 이 문서의 주소는 결제 도메인을 `maeum-ieu.vercel.app`으로 정했다고 가정합니다. 다른 도메인으로 정하면(0단계) 문서의 주소를 모두 그 도메인으로 바꿉니다.
- 환경 변수 이름과 설명은 `.env.example`의 '웹 결제' 묶음에도 있습니다.

## 1. DB 준비 — 결제 코드가 운영에 배포되기 전에

**할 일**
1. 내 컴퓨터의 `.env`에 있는 `DATABASE_URL`이 운영 DB를 가리키는지 확인합니다. 아래 스크립트는 `.env`를 읽어 그 DB에 적용합니다.
2. 저장소 맨 위 폴더에서 차례로 실행합니다.

```bash
npx tsx scripts/ops-billing-pg.ts
npx prisma generate
```

- 스크립트가 하는 일
  - 구독 표(`Subscription`)에 포트원용 칸을 더합니다. 기존 Play 구독은 그대로입니다(`provider` 기본값 'play').
  - 새 표 3개를 만듭니다: 결제 원장 `BillingPayment`, 동의 기록 `BillingConsent`, 웹훅 처리 기록 `BillingWebhookEvent`. 계정이 지워져도 결제·동의 기록은 5년 동안 남도록 연결(FK)을 걸지 않습니다.
  - 어르신 한 명에게 살아 있는 포트원 이용권이 하나만 있도록 DB가 막는 인덱스를 만듭니다.
- 추가만 하고 아무것도 지우지 않습니다. 여러 번 실행해도 안전합니다.
- **10-22 저녁 이전에 한 번 실행했어도 다시 실행합니다.** 검토 반영으로 칸이 더 늘었습니다: `Subscription.freeTurnLimit`(가입 당시 무료 한도), `BillingPayment.paidMailAt`(결제 완료 메일 보낸 시각)·`cancelType`·`cancelRequestedAt`(해지·청약철회 종류와 신청 시각 — 5년 보관 기록), `BillingConsent.offer`(동의할 때 안내한 요금제·금액·한도·결제수단·혜택 받는 분). 이미 있는 칸은 건너뜁니다.
- **`prisma db push`는 절대 쓰지 않습니다**(raw SQL 표를 지운 사고가 있었습니다).
- `npx prisma generate`는 내 컴퓨터의 Prisma 클라이언트를 맞추는 명령입니다. Vercel은 빌드할 때(`npm run build`) 자동으로 실행합니다.

**순서가 중요한 이유**: 새 코드는 구독 표의 새 칸을 읽습니다. 칸이 없는 DB에 새 코드가 먼저 올라가면 웹 결제 기능이 실패합니다(위급 기능은 영향 없음). Play 쪽은 방어해 두었습니다 — 구독 권리 조회는 없는 칸 오류(P2022)면 예전 칸으로 다시 묻고, Play 구매 확인(verify)·RTDN은 돌려받는 칸을 id로만 좁혔습니다(10-22 검토). 그래도 원칙은 **이 단계를 먼저**입니다. 메인이 결제 코드를 main에 올리기 전에 이 단계를 실행하고, 끝났다고 알려 주세요.

**필요한 것**: 운영 DB에 접속되는 `.env`, `scripts/ops-billing-pg.ts`가 들어 있는 최신 저장소

**끝났는지 확인**
- `컬럼 확인: Subscription.provider` 같은 줄이 이어지고, `인덱스 확인: Subscription_portone_live_beneficiary_key`가 보입니다.
- 마지막에 네 표(`Subscription`, `BillingPayment`, `BillingConsent`, `BillingWebhookEvent`)의 칸 목록이 찍히고, `Subscription` 목록에 `provider`, `priceKrw`, `billingKeyEnc`가 있습니다.
- `다음 단계: npx prisma generate`가 나온 뒤, generate가 Prisma Client를 만들었다고 알립니다.
- `"Subscription" 표가 없습니다`가 나오면 먼저 `npx tsx scripts/ops-create-subscription.ts`를 실행하고 다시 합니다. `실패:`로 시작하는 줄이 나오면 그 내용을 메인에게 보냅니다.

**예상 기간**: 10분

## 2. 포트원 가입·키 발급

**할 일**
1. https://admin.portone.io/auth/signup 에서 가입하고, 인증 메일을 확인한 뒤 로그인합니다. 계약 없이 무료입니다.
2. **상점 아이디**를 복사합니다: [결제 연동] > [연동 관리] > [연동 정보] 화면 오른쪽 위. → `PORTONE_STORE_ID`
3. **V2 API Secret**을 발급합니다: [연동 관리] > [식별코드·API Keys] > [V2 API] > '새로운 API Secret 발급'. → `PORTONE_API_SECRET`
   - Owner나 Admin 계정만 발급할 수 있습니다.
   - 값은 발급 직후 **한 번만** 보입니다. 바로 Vercel(4단계)에 넣으세요.
   - 발급할 때 정한 **만료일을 달력에 적어 두세요**. 만료되면 그다음 자동결제가 모두 실패합니다.

**필요한 것**: 이메일 주소(사업자 서류는 7단계에서)

**끝났는지 확인**: `store-`로 시작하는 상점 아이디와 API Secret이 있고, 만료일을 달력에 적었다.

**예상 기간**: 10분. 가입과 테스트는 무료이고, 포트원 이용료는 월 순거래액 5,000만 원 미만이면 0원입니다.

## 3. 테스트 채널·테스트 웹훅

**할 일**
1. **테스트 채널 2개**: [결제 연동] > [연동 관리] > [채널 관리] > [+ 채널 추가]에서 연동 모드 '테스트' → 결제대행사 → 결제 모듈 → 채널 이름 → 채널 속성 '결제' → 공용 테스트 아이디 순서로 고르고 저장합니다. 저장한 뒤 채널 목록에 보이는 **채널 키**(`channel-key-`로 시작)를 복사합니다.

| 채널 | 결제대행사·모듈 | 공용 테스트 아이디 | 넣을 환경 변수 |
|---|---|---|---|
| 카드 정기결제 | KG이니시스(V2) | INIBillTst | `PORTONE_CHANNEL_KEY_CARD` |
| 카카오페이 정기결제 | 카카오페이, 모듈 '결제창 일반/정기결제' | TCSUBSCRIP | `PORTONE_CHANNEL_KEY_KAKAOPAY` |
| 네이버페이 | 지금은 만들 수 없음(12단계) | 없음 | `PORTONE_CHANNEL_KEY_NAVERPAY`는 비워 둠 |

2. **테스트 웹훅**: [결제 연동] > [연동 관리] > [결제알림(Webhook) 관리] 탭에서 설정합니다.
   - 웹훅 버전: '결제모듈 V2'(날짜 버전을 고르는 칸이 있으면 최신 `2024-04-25`)
   - 설정 모드: '테스트'
   - 웹훅 URL: `https://maeum-ieu.vercel.app/api/billing/portone/webhook`
   - Content-Type: `application/json`
   - **먼저 저장**한 뒤 [웹훅 시크릿 발급]을 누릅니다. → `PORTONE_WEBHOOK_SECRET`
   - '호출 테스트'는 4단계에서 서버에 값을 넣고 다시 배포한 뒤에 합니다. 호출 테스트는 **저장된** 주소로만 갑니다.

**필요한 것**: 2단계 계정

**끝났는지 확인**: 채널 목록에 테스트 채널 2개가 있고, 테스트 모드 웹훅에 URL이 저장돼 있고, 웹훅 시크릿이 있다.

**예상 기간**: 30분

## 4. Vercel 환경 변수·예약 작업

   - 404: 결제 코드가 아직 배포되지 않았습니다.

    - 의사 계정에는 결제 화면이 없다.
    - 혜택을 받은 어르신 계정에서 이용권(하루 대화 N회)이 적용된 것이 보인다.
    - 앱(MaeumApp) 안에서 들어갈 수 있는 화면(로그인 화면 하단, 구독 화면으로 가는 버튼이 있으면 그 화면)에 요금제·웹 가격·결제수단·'웹에서 결제' 문구·링크가 없다. 앱 구독 화면에는 구독 상태만 보인다(`BILLING_PLAY_ENABLED`가 없으면 Play 구매 버튼도 없음).
13. **예약 작업**: `/api/cron/billing`을 한 번 실행합니다. Production 배포 화면의 요약(Deployment Summary)에 있는 Cron Jobs에서 실행하거나, 터미널에서 `vercel crons run /api/cron/billing`(베타 기능)을 씁니다. Settings → Cron Jobs → View Logs에서 200이고 `[billing-cron] 대사 실패` 같은 오류가 없는지 봅니다.
14. **정리**: 남은 시험 구독은 모두 '지금 해지'(7일 안이면 청약철회)로 끝냅니다. 남겨 두면 다음 달에 시험 예약 결제가 실행됩니다. 콘솔(테스트 모드)에 남은 예약이 없는지 확인합니다.
    - 시험 결제·환불 기록은 원장에 남습니다(결제 기록은 지우지 않는 설계). 시험은 시험 계정으로만 합니다.
    - 7단계 심사 기간에는 심사관이 결제창을 봐야 하므로 스위치를 켜 둡니다. 켜 두기 전에 결정 6을 확인하세요.

**결제 화면이 안 보일 때**
- `/pricing`이 404이면 결제를 열 수 없는 상태입니다(이 화면은 그때 없는 페이지가 됩니다). 아래를 차례로 봅니다.
- Vercel 로그(Logs)에서 `[billing-pg]`를 찾습니다.
  - `BILLING_PLANS 형식 오류 — 유료 요금제를 노출하지 않는다: day20: 하루 20회가 무료 한도(100회) 이하`: 무료 한도(`DAILY_TURN_LIMIT`)가 유료 요금제 한도보다 크거나 같습니다(결정 1). `BILLING_PLANS` 오타여도 같은 줄이 나옵니다. 하나라도 틀리면 요금제를 전부 숨깁니다.
- `BILLING_PG_ENABLED`가 정확히 `1`인지 봅니다.
- 필수 값이 다 있는지 봅니다: `PORTONE_STORE_ID`, `PORTONE_API_SECRET`, `PORTONE_WEBHOOK_SECRET`, `ENCRYPTION_KEY`, 채널 키 1개 이상, 팔 수 있는 요금제 1개 이상, `PORTONE_MODE`(`test`·`live` 중 하나를 **꼭** — 비우면 꺼짐), `CRON_SECRET`, `SERVICE_GMAIL_USER`·`SERVICE_GMAIL_APP_PASSWORD`(`GMAIL_USER`와 다른 계정), `BIZ_*` 8개(`BIZ_HOSTING` 제외). 빠진 이름은 Vercel 로그의 config 503 응답 근처에 남습니다.
- 결제 화면은 보이는데 "지금은 시험 운영 중이라 이용권을 신청할 수 없어요"가 나오면 그 계정이 `PORTONE_TEST_USER_IDS`에 없습니다.
- 값을 바꾼 뒤 다시 배포했는지 봅니다.
- 앱 안에서 보고 있지 않은지 봅니다. 앱에서는 원래 보이지 않습니다.

**필요한 것**: 보호자 시험 계정(어르신 계정이 연결된 것), 어르신·의사 시험 계정, 본인 카드, 카카오톡(카카오페이 테스트), PC와 휴대폰 브라우저, MaeumApp

**끝났는지 확인**: 위 1~14가 모두 맞고, Vercel 로그에 `[billing-pg]`·`[billing-mail]`·`[billing-cron]` 경고가 없고, `[결제]`로 시작하는 운영 경보 메일이 오지 않았다.

**예상 기간**: 1~2시간

**지금 확인할 수 없는 것**: 다음 달 예약 결제의 실제 실행, 결제 3일 전 안내 메일, 결제 실패 뒤 재시도(1일 뒤·3일 뒤 오전 10시). 한 달을 기다리지 않고 보려면 메인과 시험 방법을 정합니다.

## 8. 카드 PG(KG이니시스) 계약·심사

**할 일**
1. PG 담당자 메일을 따라 전자계약이나 우편으로 계약서와 서류를 냅니다. 서류는 모두 발급 3개월 이내여야 하고, 최종 목록은 PG 메일을 따릅니다.

   - 법인: 계약서 2부, 사업자등록증 사본, 법인 통장 사본, 대표자 신분증 사본, 법인인감증명서, 법인등기부등본, 실제 소유자 확인 서류(주주명부 등), 사용인감계(사용인감을 쓸 때)
2. 보증보험은 PG가 요구할 때만 듭니다(SGI서울보증, 1년 단위, 보험료는 보험금액 × 기준요율 약 0.953%).
3. 입점심사를 통과하면 **정기결제용 MID**를 받습니다. 단건 MID와 별개이고, 카드사 심사 전에 먼저 열어 주는 '바로오픈'은 정기결제에 쓸 수 없습니다.
4. PG가 카드사 심사를 요청합니다(보통 2주). 심사가 끝나기 전에는 실결제가 실패하는 게 정상입니다.
5. 이니시스 상점관리자 > 상점정보 > 부가정보에서 웹표준 signkey, INILite Key, INIAPI key를 찾아 둡니다(10단계에 필요).

**필요한 것**: 0단계 정산계좌, 서류, (요구 시) 보증보험

**끝났는지 확인**: 정기 MID와 키 3개가 있고, 카드사 심사 완료 안내를 받았다.

**예상 기간**: 계약·서류 약 1주 + 카드사 심사 약 2주(통상 3주 안팎)

## 10. 실연동 전환(`PORTONE_MODE=live`)

**할 일**
1. **시험 구독 정리**: 남은 시험 구독을 모두 '지금 해지'로 끝내고, 콘솔(테스트 모드)에 남은 결제 예약이 없는지 확인합니다. 남겨 두면 전환 뒤 그 예약의 결과가 채널 불일치로 처리돼 혜택 없이 `[결제] 금액·빌링키 불일치` 운영 경보가 납니다.
2. **실연동 채널 만들기**: [채널 관리] > [+ 채널 추가]에서 연동 모드 **'실연동'**
   - KG이니시스(V2): 정기 MID, 웹표준 signkey, INILite Key, INIAPI key
   - 카카오페이: 정기 CID(CA…), 모듈 '결제창 일반/정기결제'
3. **실연동 웹훅**: [결제알림(Webhook) 관리]에서 설정 모드 '실연동'으로 같은 URL(`https://maeum-ieu.vercel.app/api/billing/portone/webhook`), Content-Type `application/json`을 저장하고 새 시크릿을 발급합니다. 테스트 모드 웹훅 설정은 지우지 않고 둡니다.
4. **Vercel 값 4개를 한 번에 바꾸고 한 번만 다시 배포합니다**.
   - `PORTONE_CHANNEL_KEY_CARD` → 실연동 카드 채널 키
   - `PORTONE_CHANNEL_KEY_KAKAOPAY` → 실연동 카카오페이 채널 키
   - `PORTONE_WEBHOOK_SECRET` → 실연동 웹훅 시크릿
   - `PORTONE_MODE` → `live`
   - `PORTONE_STORE_ID`와 `PORTONE_API_SECRET`은 그대로 둡니다.
   - 섞인 상태(채널은 실연동인데 모드는 test이거나 그 반대)로 두면 결제가 확인 단계에서 거절됩니다.
5. 실연동 웹훅에서 '호출 테스트'를 눌러 200을 확인합니다.
6. **실결제 확인**: 본인 카드로 가장 싼 요금제를 결제합니다. 결제 완료 메일, 구독 관리 화면, 콘솔(실연동)의 결제완료와 다음 달 예약을 확인한 뒤 '지금 해지'(7일 안 — 청약철회)로 전액 돌려받습니다. 카드사 취소 알림까지 확인합니다. 카카오페이도 한 번 같은 순서로 합니다.

**필요한 것**: 8·9단계의 MID·키·CID, 본인 카드와 카카오페이(실제 돈이 나가고 청약철회로 돌려받음)

**끝났는지 확인**: 실결제 2건이 결제부터 전액 환불까지 정상이고, 운영 경보 메일과 Vercel 로그 경고가 없다.

**예상 기간**: 1~2시간. 카드사 심사가 끝나기 전에는 실결제가 실패하는 게 정상이니 심사 완료 안내를 받은 뒤 합니다.

## 11. 오픈

**할 일**
1. 메인에게 약관·환불정책의 **시행일**을 실제로 여는 날로 고쳐 달라고 합니다(`lib/billing/pg-terms.ts`의 `PG_TERMS_EFFECTIVE` — 지금 "2026년 10월 22일"). 먼저 적힌 날짜로 열면 그날부터 시행된 것처럼 보입니다.
2. `BILLING_PG_ENABLED=1`을 그대로 둡니다. 비상시 끄려면 값을 지우고 다시 배포합니다.
   - 끄면 새 가입(요금 안내·결제 시작)만 막힙니다. 이미 가입한 이용권의 갱신 결제·해지·환불·웹훅·예약 작업·약관 화면은 상점 아이디(`PORTONE_STORE_ID`)가 있는 한 계속됩니다.
   - 가입자가 있을 때 키를 지우지 않습니다(포트원은 예약 결제를 그대로 실행). `PORTONE_STORE_ID`를 지우면 해지 화면까지 꺼지고, `PORTONE_API_SECRET`을 지우면 해지 의사는 기록되지만 환불·예약 취소가 멈추고 예약 작업이 매일 운영 경보(`[결제] 포트원 API Secret 없음`)를 보냅니다.
3. 보호자에게 웹 결제를 알릴 때는 메일 등 **앱 밖**에서만 합니다. 앱 안에는 웹 결제 안내를 넣지 않습니다(13단계).
4. 첫 가입자의 첫 갱신(한 달 뒤)을 지켜봅니다: 3일 전 안내 메일 → 결제일 오전 10시 예약 결제 → 콘솔의 예약 상태 SUCCEEDED → 결제 완료 메일.

**끝났는지 확인**: 첫 실가입자의 첫 갱신 결제와 메일까지 정상이다.

## 12. 네이버페이(카드 오픈 후)

**조건**: 사이트에 카드 결제가 붙어 있고, **최소 1개월(신청 직전 달) 카드 실매출**이 있어야 합니다. 카드 PG 계약에서 **네이버페이 간편결제는 켜지 마세요**. PG를 통해 네이버페이를 제공하고 있으면 직가맹(결제형) 입점이 되지 않습니다.

**먼저 할 일**: 13단계의 네이버페이센터 문의(앱의 Play 결제 모듈)를 먼저 끝냅니다.

**할 일**
1. 포트원 콘솔 신청 내역에서 '전자 결제를 추가할게요'로 네이버페이(결제형)를 추가합니다.
2. 네이버페이 안내 메일이 오면 네이버페이센터에서 가입신청서를 씁니다. **실명인증된 개인 네이버 ID**로 작성합니다.
   - 운영 형태: "호스팅사 쇼핑몰 구축 서비스를 운영해요", 호스팅사명 **코리아포트원**
   - 결제방식: **정기결제**(단건 판매 계획이 있으면 '일반결제+정기결제' — 나중에 추가하면 상점아이디를 새로 받고 검수도 다시 함)
   - 현금영수증: '네이버페이 대행' 권장 · 정산 기준: '결제일 기준' 권장
   - 서류: 사업자등록증 사본(1년 이내 발급분), 법인이면 법인등기부등본(3개월 이내)과 주주명부
   - 매출 증빙 2종: PG 월별 매출 요약 이미지, PG 연동 URL 이미지(jpg·gif·pdf, 항목당 5MB, 주민번호 뒷자리 가림)
   - 고객확인(KYC)을 입력한 뒤 **'심사요청' 버튼까지** 눌러야 심사가 시작됩니다.
3. 1차 심사(접수 후 최대 1주)를 통과하면 승인 메일로 Shop ID(np_…), Client ID, Client Secret, Chain ID를 받습니다. 이 값은 포트원 채널 설정에 넣는 값이고, Vercel에는 넣지 않습니다.
4. **검수용 환경을 메인과 먼저 정합니다**: 이때 운영은 `PORTONE_MODE=live`라서, 네이버페이 **테스트** 채널로 한 결제를 운영 서버가 받아들이지 않습니다. 검수(테스트 채널 결제)를 어디서 받을지 정한 뒤 진행합니다(결정이 필요한 것 참고).
5. 포트원에 네이버페이 '테스트' 채널을 만듭니다(PG상점아이디 `naverpay-partner`, 나머지는 승인 메일 값).
6. 네이버페이센터 > 내 정보 > 가입정보 변경에서 **정기결제 체크리스트**를 내려받아 작성합니다.
7. 검수를 요청합니다(포트원 안내는 tech.support@portone.io — 창구는 신청 때 확인). 상호, 사업자번호, 포트원 계정, 담당자 연락처, 정기 파트너ID, 검수 URL, 테스트 로그인 계정, 질의사항 답변(적립·현금영수증·과세/면세·에스크로·앱 보유 여부·부분취소·위변조 방지), 정기결제 요청서를 보냅니다.
8. 검수가 끝나면 '실연동' 채널을 만들고, 그 채널 키를 `PORTONE_CHANNEL_KEY_NAVERPAY`에 넣고 다시 배포합니다. 본인 계정으로 실결제와 청약철회를 한 번 확인합니다.

**주의**: 환불은 원래 결제수단 취소로만 합니다(자체 현금 환불 불가). 사이트 하단 정보는 사업자등록증·공정위 조회 정보와 같아야 합니다. 검수가 시작되기 전 운영 결제창의 "API 호출 권한이 없습니다" 오류는 정상입니다.

**끝났는지 확인**: 운영 사이트에 네이버페이 버튼이 보이고 실결제·환불이 된다.

**예상 기간**: 1차 심사 최대 1주 + 검수 약 2주(평균 15영업일). 카드 오픈부터 따지면 약 2개월(추정)입니다.

## 14. 운영하면서 챙길 것

- **API Secret 교체**(만료 전): 새로 발급 → Vercel `PORTONE_API_SECRET` 교체 → 다시 배포 → 이전 Secret 삭제.
- **웹훅 시크릿 교체**: 모드별로 2개까지 동시에 둘 수 있습니다. 새로 발급 → Vercel `PORTONE_WEBHOOK_SECRET` 교체 → 다시 배포 → 이전 시크릿 만료.
- **운영 경보 메일**: `[결제]`로 시작하는 메일(`OPS_ALERT_EMAIL`, 없으면 결제 안내 메일 계정 `SERVICE_GMAIL_USER`의 받은편지함)이 오면 메인에게 보냅니다. 예: `[결제] 금액·빌링키 불일치`, `[결제] 예정 결제가 하루 넘게 결과 없음`, `[결제] 예약 작업 대사 실패`, `[결제] 포트원 API Secret 없음`, `[결제] 포트원에서 취소된 예약`.
- **예약 작업 로그**: 가끔 Vercel Settings → Cron Jobs → View Logs를 봅니다.
- **전화·이메일 해지·환불 요청**: 웹의 구독 관리 화면(`/expert` 머리·`/mypage`의 '구독 관리')에서 직접 하도록 먼저 안내합니다. 대신 처리해야 하면 본인 확인(결제회원 본인 — 가입 이메일·결제 내역 대조) 뒤 `scripts/ops-billing-cancel.ts`로 **신청 시각 기준**으로 처리합니다(6일째 받은 철회 메일을 9일째 처리해도 청약철회 — 법상 철회는 의사를 보낸 때 효력이 생김).

```bash
npx tsx scripts/ops-billing-cancel.ts <구독 id> now 2026-11-08T21:30:00+09:00          # 미리보기(아무것도 바꾸지 않음)
npx tsx scripts/ops-billing-cancel.ts <구독 id> now 2026-11-08T21:30:00+09:00 --yes    # 실제 해지·환불
```

  - `now`는 지금 해지(신청 시각이 7일 안이면 청약철회), `period_end`는 다음 결제부터 해지입니다. 신청 시각은 메일 수신·통화 시각을 그대로(한국 시간이면 `+09:00`).
  - 미래 시각, 30일보다 오래된 시각, 신청 뒤 결제된 회차가 있으면 처리하지 않고 이유를 보여 줍니다 — 메인에게 넘깁니다.
  - 포트원 콘솔에서 결제만 취소하지 않습니다(다음 달 결제 예약이 그대로 남습니다).
- **가격 인상**: 이미 가입한 사람은 가입 당시 가격을 유지합니다. 올리려면 30일 전 안내와 따로 받는 동의가 필요한데, 그 화면은 아직 없습니다(개발 필요). 새 가격은 `BILLING_PLANS`를 바꾸면 새 가입자에게만 적용됩니다.
- **포트원 이용료**: 월 순거래액이 5,000만 원을 넘으면 유료로 바뀝니다(Growth 1: 월 10만 원, VAT 별도).
- **정보 변경**: 상호, 주소, 전화, 도메인, 호스팅이 바뀌면 통신판매업 변경신고(15일 이내), 포트원 '정보 수정 요청', `BIZ_*` 교체·다시 배포를 합니다. 서비스나 결제 방식이 바뀌면 PG 재심사를 받습니다.
- **원가 재점검**: 2026년 말에 요금제를 다시 봅니다(2027년 1월부터 1회 대화 원가 약 22원 — 결정 2의 표).
- **기록 보관**: 결제·환불·동의 기록은 계정이 지워져도 5년 동안 보관합니다(전자상거래법 시행령 제6조). 지우지 않습니다.

## 코드와 대조할 것(메인 최종 대조용)

이 문서는 설계서 '조사 반영 결정'의 이름으로 썼습니다. 작업이 끝난 뒤 실제 코드와 대조해 다른 곳은 이 문서를 고칩니다. '(10-22 저녁 대조)'라고 적은 항목은 그 시점 작업 트리의 코드로 이미 맞춰 본 것이고, 그 뒤 바뀌었는지만 보면 됩니다.

1. **배포 순서**: 새 Prisma 클라이언트가 `Subscription`의 새 칸(`provider`·`dailyTurnLimit` 등)을 읽으므로, 사용자가 1단계(`scripts/ops-billing-pg.ts`)를 운영 DB에 실행한 뒤에 main에 푸시합니다. 순서가 바뀌면 `getEntitlement`가 조회 실패로 무료로 떨어지고 Play `verify`의 구독 생성도 실패할 수 있습니다.
2. **경로**: `/api/billing/portone/{config,prepare,activate,webhook,cancel,refund}`, `/api/cron/billing`, `/subscribe`, `/subscribe/return`, `/pricing`, `/terms/paid`, `/terms/refund`가 이 문서와 같은지(10-22 저녁 대조: `/subscribe/return`만 아직 없었고 나머지는 있음. `/subscribe`는 아직 PG 화면으로 바뀌기 전).
3. **웹훅**(10-22 저녁 대조: `app/api/billing/portone/webhook/route.ts`): 서명 실패 400, 처리·재전송·다른 상점 200, 내부 오류·시크릿 형식 오류 500, 포트원 키나 웹훅 시크릿이 없으면 503. 판매 스위치와 무관하고 `BillingKey.Issued`만 스위치를 따릅니다. 4단계 6번의 응답 코드 안내가 이것과 같은지.
4. **middleware**: `/pricing`, `/terms/*`, `/api/billing/portone/webhook`, `/api/cron/billing`이 로그인 없이 열리는지(10-22 저녁 대조: `middleware.ts` matcher에 없어 열림 — 그 뒤 바뀌었는지).
5. **스위치 판정**(10-22 검토 반영: `lib/billing/portone-plans.ts`): `BILLING_PG_ENABLED`가 정확히 "1"(`lib/flags` `flagOn`) + `pgConfigProblems()`의 필수 목록(`PORTONE_STORE_ID`·`PORTONE_API_SECRET`·`PORTONE_WEBHOOK_SECRET`·`ENCRYPTION_KEY`·채널 키 1개 이상·요금제 1개 이상·`PORTONE_MODE` test|live 명시·`CRON_SECRET`·`SERVICE_GMAIL_*`(위급 메일 계정과 다름)·`BIZ_*` 8개)이 5단계 '결제 화면이 안 보일 때'와 같습니다.
6. **스위치를 끌 때 기존 구독**(10-22 검토 반영: `lib/billing/portone-route.ts` `pgGate`·`portoneServiceable`): 판매(sales — config·prepare·activate)는 `isPgEnabled()`, 돌봄(service — 해지·환불·결제 웹훅·예약 작업·구독 관리 정보·약관 화면)은 **상점 아이디만** 봅니다(API Secret이 빠져도 해지 화면이 꺼지지 않게 — Secret이 없으면 예약 작업이 운영 경보). 11단계 2번은 이 동작으로 썼습니다. 설계서 0의 "PG API 전부 꺼짐"과 다르게 한 이유가 코드 주석(해지 방해 방지)에 있으니 메인이 받아들일지 판단합니다.
7. **시험 기간 노출(결정 6)**: 적용됨 — 시험(test) 모드의 prepare는 `PORTONE_TEST_USER_IDS` 밖 계정을 403 `test_mode_restricted`로 막고, config는 `testModeRestricted`를 내려 화면이 '시험 운영 중' 안내를 보입니다.
8. **네이버페이 검수(결정 12)**: `PORTONE_MODE` 하나로는 운영 live 상태에서 테스트 채널 결제를 받지 못합니다.
9. **무료 한도 의존**: `parsePgPlans`가 무료 한도 이하 요금제가 하나라도 있으면 전부 버리는 것(코드 기본 100이면 임시 3개 전부)이 의도인지. 경고 문구는 10-22 저녁 대조로 5단계 설명과 같습니다(scratch 시험으로 무료 한도 10이면 `.env.example` 예시 3개 통과, 100이면 "무료 한도(100회) 이하"로 전부 버려짐을 확인).

16. **일반인 결제(결정 3)**: 막음 — config `canPurchase`는 보호자만, `resolvePgBeneficiary`는 결제회원이 보호자이고 혜택 받는 분이 어르신(user) 계정일 때만 받습니다. 구독 상태의 오늘 대화 수(한도)도 어르신 계정에만 싣습니다.
17. **역할별 화면**: 어르신 계정의 "보호자께 부탁하세요" 안내, 의사 계정 결제 화면 숨김(5단계 12번).
18. **앱 판별**(10-22 검토 반영: `lib/billing/portone-route.ts`): 새 가입은 `isAppWebViewRequest` — `X-Requested-With: com.maeumapp`, UA의 `MaeumApp/`, 또는 Android WebView 표지 `; wv)`(카카오톡·네이버·인스타그램·구글 앱(GSA)·덕덕고·당근·토스·카카오페이 등 다른 앱의 인앱 브라우저 표지가 없고, `X-Requested-With`가 다른 앱 패키지가 아닐 때)면 앱으로 보고 403. 해지·환불·구독 관리 정보(status pg)는 `isDefiniteAppRequest` — 앱 패키지 헤더나 `MaeumApp/` 접미사일 때만(목록 밖 인앱 브라우저에서 해지가 막히지 않게). ⚠ 지금 앱은 UA 접미사를 붙이지 않습니다 — 다음 앱 버전에서 `applicationNameForUserAgent="MaeumApp/x.y"`를 붙이면 서버가 `; wv)` 추측 없이 가릴 수 있습니다(앱 저장소 TODO). 휴대폰 크롬과 카카오톡 인앱 브라우저를 막지 않는지는 5단계 11번이 실기기 확인입니다.
19. **약관 문구 버전·시행일**(10-22 저녁 대조): 문안을 고치면 `lib/billing/portone-consent.ts`의 `PG_TERMS_VERSION`(지금 "2026-10-22")을 올립니다(6단계 약관 검토). 여는 날 `lib/billing/pg-terms.ts`의 `PG_TERMS_EFFECTIVE`를 그날로 고칩니다(11단계 1번).
20. **운영자 대리 처리**: `scripts/ops-billing-cancel.ts`(lib/billing/portone-ops-cancel — 신청 시각 기준, 미리보기 후 `--yes`). 신청 뒤 결제된 회차가 있는 경우는 처리하지 않습니다(사람이 확인 — 14단계).
21. **요청마다 그리기**(10-22 저녁 대조): `/pricing`·`/terms/paid`·`/terms/refund`는 `connection()`으로 요청마다 그려 `BILLING_PLANS`·`BIZ_*`가 빌드 때 고정되지 않습니다. `/subscribe`·`/subscribe/return`·`/privacy`·`/login` 하단도 같은지.
22. **배포 점검 스크립트**: `scripts/check-env.ts`에 웹 결제 변수 점검이 없습니다. 그래서 이 문서의 확인법은 화면과 로그 기준입니다. 추가할지 판단합니다.
23. **탈퇴·연결 해제**: 계정 삭제·보호자 연결 해제 경로가 해지 함수(`cancelForPurchaserDeletion`·`cancelForBeneficiaryGone`)를 삭제·해제 **전에** 부르는지. 연결하면 5단계에 시험 항목을 더합니다. 연결 해제는 포트원 장애로 막히지 않습니다(해지 의사를 DB에 먼저 적고 포트원 정리 실패는 운영 경보 — 10-22 검토).
24. **결제 복귀 화면**(10-22 검토 반영): 쿼리의 실패 문구는 그 issueId가 지금 로그인한 사람의 최근(1시간 안) 발급 시도일 때만 그대로 보이고, 아니면 고정 안내입니다(`lib/billing/portone-return.ts` — 남이 만든 링크로 피싱 문구를 띄우지 못하게). 첫 결제 확정 결과를 모르면(로그인 없음·네트워크·일시 오류) 실패라 하지 않고 '확인 중' + 로그인 링크를 보입니다. 쿼리(빌링키 포함)는 화면이 뜨자마자 주소창에서 지웁니다 — 서버 접근 로그에는 남습니다(forceRedirect를 쓰는 한 피할 수 없음 — 빌링키만으로는 결제할 수 없고 API Secret이 필요).
25. **약관 화면**(10-22 검토 반영): `/terms/paid`·`/terms/refund`는 판매가 켜졌거나 상점 아이디가 있을 때만 열립니다(아니면 404 — 설정 없이 배포해도 초안이 공개되지 않게). 하단 링크도 같은 조건이고, 요금 안내 링크는 판매 중에만입니다.
26. **처리방침·계정 삭제 안내**: 웹 결제 문단과 시행일(10월 22일)은 **배포하는 즉시** 바뀝니다(판매 스위치와 무관 — 법정 고지 문서를 env로 두 판으로 나누지 않았습니다). 실제 계약한 PG로 수탁자 이름을 확정하고 시행일을 실제 게시일로 고친 뒤에 내보냅니다(메인·사용자 결정).
