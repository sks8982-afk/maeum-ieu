# 구독 결제 설정 · 재빌드 · 재심사 절차

작성: 2026-10-01 · 대상: 마음이음 v1.1.0(구독 결제 포함)

코드는 모두 들어가 있고 **기본값은 "아무것도 막지 않음"** 입니다.
아래 설정을 끝낸 뒤 환경변수 하나(`BILLING_ENFORCE=1`)로 유료 기능 차단을 켭니다.

---

## 0. 먼저 정해야 하는 것 — 가격

실측 원가(2026-09-30, 캐시 할인 반영): **턴당 약 $0.0074 ≈ 10원**

| 하루 대화량 | 월 LLM 원가(1인) |
|---|---|
| 10턴 | 약 3,100원 |
| 20턴 | 약 6,200원 |
| 30턴 | 약 9,400원 |
| 60턴 | 약 18,800원 |
| 100턴 | 약 31,000원 |

**가격은 유료 상한의 원가보다 충분히 높아야 합니다.** 예를 들어 월 9,900원에 하루 60턴을
주면 원가가 18,800원이라 쓰는 사람이 많을수록 적자가 커집니다.

현재 설정값:
- 무료 상한 `DAILY_TURN_LIMIT` = 100 (원가 월 31,000원) — **출시 전에 낮추는 것을 권합니다**
- 유료 상한 `PRO_DAILY_TURN_LIMIT` = 미설정 → 무료의 3배

> 무료 100턴은 "제한을 도입하되 기존 사용자 조건을 낮추지 않는다"는 전제로 둔 값입니다.
> 유료 전환을 기대한다면 무료는 10~20턴, 유료는 40~60턴 선이 원가와 가격 사이에서 맞습니다.

## 1. Play Console — 구독 상품 만들기

1. Play Console → 마음이음 → **수익 창출 → 구독**
2. [구독 만들기]
   - 상품 ID: 예 `maeum_monthly` (한 번 정하면 못 바꿉니다)
   - 이름/설명: 어르신·보호자가 읽는 문구
3. **기본 혜택(base plan)** 추가
   - 결제 주기: 월
   - 가격: 0단계에서 정한 금액 (한국 원화)
   - ⚠️ 기본 혜택이 **활성** 상태여야 앱에서 `offerToken`을 받을 수 있습니다.
     비활성이면 구매 버튼이 "구독 상품 정보를 불러오지 못했습니다"로 끝납니다.
4. 저장 후 상품 ID를 환경변수에 넣습니다 → `BILLING_PRO_PRODUCT_IDS=maeum_monthly`

---

## 2. 서비스 계정 — 구매를 서버에서 검증하기

구매 토큰을 Google에 직접 확인해야 위조·재사용을 막을 수 있습니다.

1. Google Cloud Console → 프로젝트 → **IAM 및 관리자 → 서비스 계정 → 만들기**
   - 이름: 예 `play-billing-verify`
   - 키 만들기 → **JSON** 다운로드
2. Play Console → **설정 → API 액세스**
   - 위 Google Cloud 프로젝트를 연결
   - 해당 서비스 계정에 권한 부여: **재무 데이터 보기**, **주문 및 구독 관리**
   - ⚠️ 권한 반영에 최대 24시간 걸릴 수 있습니다(바로 403이 나면 기다려 보세요)
3. Vercel 환경변수에 등록

```
PLAY_PACKAGE_NAME=com.maeumapp
PLAY_SERVICE_ACCOUNT_JSON=<JSON 원문 또는 base64>
```

base64로 넣는 쪽이 안전합니다(개행 때문에 깨지지 않음):

```bash
base64 -w0 play-billing-verify.json
```

## 3. RTDN — 갱신·해지·환불을 서버가 알게 하기

이걸 설정하지 않으면 **해지한 사람이 계속 혜택을 받습니다**(만료 시각이 지나면 끊기지만,
환불·보류는 반영되지 않습니다).

1. 공유 비밀 생성 후 Vercel에 등록

```bash
openssl rand -hex 32
```

```
BILLING_RTDN_SECRET=<생성한 값>
```

2. Google Cloud → **Pub/Sub → 주제 만들기** (예: `play-rtdn`)
   - 주제 권한에 `google-play-developer-notifications@system.gserviceaccount.com`을
     **Pub/Sub 게시자**로 추가 (이게 없으면 Play가 발행하지 못합니다)
3. 같은 주제에 **푸시 구독** 만들기
   - 엔드포인트 URL:
     `https://maeum-ieu.vercel.app/api/billing/rtdn?secret=<BILLING_RTDN_SECRET>`
4. Play Console → 마음이음 → **수익 창출 설정 → 실시간 개발자 알림**
   - 주제 이름 입력 → [알림 테스트 보내기]
   - Vercel 로그에 `[rtdn] 테스트 통지 수신 — 연결 정상`이 보이면 성공

## 4. 재빌드 (AAB)

v1.1.0은 **네이티브 의존성이 추가**되었습니다(`react-native-iap` + `react-native-nitro-modules`).
JS만 바뀐 게 아니므로 반드시 새로 빌드해야 합니다.

```bash
cd MaeumApp
npm install                       # react-native-iap 설치 확인
cd android
./gradlew clean
./gradlew bundleRelease           # → app/build/outputs/bundle/release/app-release.aab
```

- 서명 키: `MaeumApp/android/app/maeum-upload.keystore` (비밀번호는 `~/.gradle/gradle.properties`)
  ⚠️ **이 키스토어를 잃으면 업데이트를 올릴 수 없습니다.** 백업을 꼭 확인하세요.
- 버전: `versionCode 5` / `versionName 1.1.0` (이미 반영됨)
- 빌드가 Nitro 모듈에서 실패하면 `android/gradle.properties`의 `newArchEnabled=true`를
  확인하세요(현재 true — 정상).

## 5. 라이선스 테스터로 실제 결제 테스트

**실제 카드 결제 없이** 전체 흐름을 확인할 수 있습니다. 이 단계를 건너뛰면 결제가
처음 동작하는 순간이 실제 사용자에게서 일어납니다.

1. Play Console → **설정 → 라이선스 테스트** → 본인 Google 계정 추가
2. AAB를 **내부 테스트** 트랙에 업로드하고 본인 계정으로 설치
3. 앱에서 로그인 → 구독 화면(`/subscribe`) → [구독하기]
4. 확인할 것
   - 결제 시트가 "테스트 카드"로 뜨는지
   - 결제 후 화면이 "구독 중"으로 바뀌는지
   - Vercel 로그에 `[billing] 검증 완료 … status=active tier=pro`
   - 보호자 계정으로 결제했다면 "혜택 적용 대상"에 어르신 이름이 나오는지
   - Play 스토어에서 해지 → 로그에 `[rtdn] 상태 갱신 … → canceled`
     (혜택은 만료일까지 유지되는 것이 정상입니다)

서버 상태는 이걸로도 확인할 수 있습니다:

```bash
npx tsx scripts/billing-verify.ts   # 실제 DB에 구독을 넣어 권리 판정 25건 검증(끝나면 삭제)
```

## 6. 유료 차단 켜기

위 테스트가 끝난 뒤에만 켭니다.

```
BILLING_ENFORCE=1
PRO_DAILY_TURN_LIMIT=<유료 상한>
DAILY_TURN_LIMIT=<무료 상한>
```

켜면 바뀌는 것:
- 보호자 화면의 **상태 요약·추세·복약 이행률**이 구독 전에는 가려집니다
- 🔒 **위급 알림과 위급 이력은 그대로 제공됩니다** — 안전 기능은 과금과 분리되어 있습니다
- 어르신 대화 상한이 구독 여부에 따라 달라집니다

끄면(또는 변수 삭제) 즉시 전부 무료로 돌아갑니다. 배포 없이 전환됩니다.

## 7. 재심사 제출

1. Play Console → **프로덕션 → 새 버전 만들기** → AAB 업로드
2. 출시 노트 예시

```
• 하루 대화량 안내를 추가했습니다
• 역할별 사용 안내(어르신·보호자·의사) 화면을 추가했습니다
• 구독 기능을 추가했습니다 (위급 알림은 구독과 무관하게 계속 제공됩니다)
• 안정성 개선
```

3. **심사에서 자주 걸리는 항목**
   - **결제**: 디지털 구독은 Google Play 결제만 사용해야 합니다. 외부 결제 링크나
     "웹에서 결제하세요" 유도를 넣으면 반려됩니다.
     → 현재 `/subscribe`는 브라우저에서 "앱에서 결제됩니다"라고만 안내합니다(링크 없음). ✅
   - **구독 정보 표시**: 가격·결제 주기·해지 방법이 구매 전에 보여야 합니다.
     → 가격은 Play 결제 시트가 표시하고, 해지 방법은 구독 화면에 적혀 있습니다. ✅
   - **민감 권한**: 마이크·알림 권한의 사용 목적이 앱 내에서 설명되어야 합니다.
     → 권한 요청 시 사유 문구 + `/help`에 안내. ✅
   - **건강 데이터**: 데이터 세이프티 양식에 "건강 및 피트니스" 수집을 신고해야 합니다.
     → 이미 신고됨. 구독 추가로 바뀌는 항목은 **"앱 내 구매"** 표시입니다 —
       스토어 등록정보에서 체크하세요.
   - **의료 기기 오인 금지**: "진단"이라는 표현을 쓰면 의료기기 심사 대상이 될 수 있습니다.
     → 전 화면이 "선별·자가점검"으로 표기되어 있고, 도움말에도 "진단이 아님"을 명시. ✅
4. 데모 계정: 기존 심사용 계정(`test1234@test.com`)을 그대로 쓰되,
   **구독 테스트는 라이선스 테스터로 하세요** — 심사관에게 유료 기능을 보여줘야 하면
   그 계정을 미리 라이선스 테스터에 넣거나, `BILLING_ENFORCE=0`으로 제출하세요.

## 8. 출시 후 점검

- `/api/billing/status`가 올바른 티어를 돌려주는지
- Vercel 로그에 `[billing]`·`[rtdn]` 경고가 쌓이지 않는지
- 특히 `승인 실패` 로그 — **3일 안에 승인되지 않은 구매는 Google이 자동 환불합니다**
- 월 1회: `npx tsx scripts/billing-verify.ts`로 권리 판정 회귀 확인
