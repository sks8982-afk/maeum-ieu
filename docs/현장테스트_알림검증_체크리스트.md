# 현장 테스트 전 위급 알림 검증 체크리스트

> **목적**: 요양원 현장 테스트(W5~W7) 투입 전, **"환자 위급 발화 → 연결된 보호자 앱에 실제 도착"**을 실기기로 검증한다.
> **근거 코드**: `lib/chat/emergency-notify.ts`(채널 통합·타깃), `lib/notify/push-fcm.ts`(토픽 발송), `lib/notify/email.ts`.
> **핵심 원리**: 앱 알림은 **환자와 코드로 연결된 보호자(ExpertPatient active)** 에게 두 사본이 **함께** 간다 — 그 보호자 계정으로 앱(1.2.0+)에 로그인해 등록된 휴대폰(실명 사본)과 개인 토픽 `maeum_<보호자id>`(가린 이름 사본 — 예: 김*자). 어르신 계정에 보호자 이메일·메신저(webhook) 주소가 등록돼 있으면 그쪽으로도 함께 보낸다. 가입 시 입력한 '전화번호'는 알림 채널이 아니다.

---

## 게이트 요약 (이 셋이 진짜 관문)
- **1. 프로덕션 env** — 없으면 알림 자체가 조용히 skip
- **3. 보호자 앱 토픽 구독** — 서버는 정확, 클라(RN 앱) 절반은 실기기 확인 필요
- **4. 종단 발송** — 실제 응급 발화로 보호자 폰에 도착

1·3·4 중 하나라도 실패하면 **"위급 시 가족 알림" 약속이 조용히 안 지켜짐 → 현장 투입 금지.**

---

## 0. 사전 준비
- [ ] 테스트용 **환자 계정**(사용자 모드) 1개
- [ ] 테스트용 **보호자 계정**('전문가·보호자' 모드) 1개 — ⚠️ 반드시 테스트 계정(진짜 가족에게 응급 알림이 가지 않게)
- [ ] 보호자용 **안드로이드 실기기** 1대

## 1. 프로덕션 환경변수 (Vercel) — 🔴 게이트
`docs/진행기록_2026-06-23.md` 명시 env가 프로덕션에 실제로 세팅됐는지:
- [ ] `FCM_SERVICE_ACCOUNT` 또는 `FCM_SERVICE_ACCOUNT_B64` — **앱 푸시**. 없으면 `push-fcm`이 graceful skip → 앱 알림 안 감
- [ ] `ENCRYPTION_KEY` — 보호자 연락처/이메일 복호화 (일상·프로드 동일 키 유지)
- [ ] `GMAIL_USER` + `GMAIL_APP_PASSWORD` — 이메일 채널 (⚠️ Gmail 앱비번 재발급했으면 프로드 env도 갱신)
- [ ] `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` — rate-limit (없으면 인메모리 폴백이나 서버리스에서 부정확)
- [ ] `GEMINI_API_KEY`, `DATABASE_URL` 등 기본
- **검증법**: Vercel 대시보드 env 확인 + 배포 런타임 로그에 `[push-fcm] ... not configured` / `서비스 계정 파싱 실패` 경고가 **없는지**.

## 2. 연결(ExpertPatient) 확립 — 알림 타깃의 전제
- [ ] 보호자 계정 로그인 → **연결 코드 발급**
- [ ] 환자 계정 마이페이지 → **코드 입력** → "연결되었어요" 확인
- [ ] DB에 `ExpertPatient(status="active")` 생성 확인
- **주의**: 설치만 하고 이 연결을 안 하면 **알림이 가지 않는다**(타깃이 없음).

## 3. 보호자 앱 토픽 구독 — 🔴 게이트 (클라 절반)
- [ ] 보호자 앱 설치(로그인 화면 APK 다운로드)
- [ ] 보호자 계정으로 **앱 로그인**
- [ ] 로그인 시 `maeum_<보호자id>` **토픽 구독**이 실제로 이뤄지는지 (앱 로그 `subscribeToTopic` 성공)
- [ ] **알림 권한 허용** + **배터리 최적화 예외** 설정 (앱 자동 안내 동작 확인)
- **검증법**: Firebase 콘솔에서 해당 토픽으로 **테스트 메시지** 발송 → 폰에 수신되는지.

## 4. 종단 발송 (실제 위급 발화) — 🔴 게이트
- [ ] 환자 계정으로 대화 → **명백한 응급 발화** 입력
  - 예: `약을 한 통 다 먹어버렸어` (medication) / `너무 힘들어서 죽고 싶어` (suicidal)
- [ ] 서버 로그: `detectEmergency` L3 → `notifyGuardian` 호출 → 결과 `channels`에 **`fcm` 또는 `fcm-topic` 포함** (`fcm-topic` = FCM이 토픽 사본을 받아들임(앱 버전과 무관, 받은 기기는 모름))
  - 휴대폰별 수신 확인(`fcm` = 알림을 허용했다고 보고한 등록 휴대폰에 닿음 · `fcm-muted` = 알림을 꺼 두었다고 보고한 등록 휴대폰에 닿음)은 앱 1.2.0부터다 — 보호자 휴대폰이 1.2.0이면 `channels`에 **`fcm`(알림을 꺼 두었으면 `fcm-muted`)도 있어야 하고**, 보호자 화면 '위급 알림을 받는 휴대폰'에 그 휴대폰이 보여야 한다. `fcm-topic`만 있으면 그 휴대폰이 등록되지 않았거나(위 보호자 화면 확인) 등록 휴대폰 경로가 실패한 것이다(운영자 경보 확인).
- [ ] 보호자 폰: **몇 초 내** 알림 도착(소리·진동), 제목/본문 정확
- [ ] **앱 완전 종료 상태에서도** 알림이 뜨는지 (notification 페이로드 → OS가 직접 표시)
- [ ] 알림 탭 → 앱 열림 / 위급 이력 화면 진입

## 5. 보조 채널 (선택)
- [ ] 보호자 **이메일** 등록 시 이메일 도착(Gmail 발신)
- [ ] (선택) **webhook URL** 등록 시 Discord 등에 POST 도착(SSRF 가드로 https·공인 IP만 허용됨)

## 6. 오탐·중복·프라이버시
- [ ] 같은 카테고리 **1시간 내 재발화** → 중복 알림 안 감 (dedup 윈도우) — **단, 첫 발송에 일시 실패·조회 실패(아래 줄)가 없었을 때만**. 영구 실패(웹훅 404·차단된 주소·앱을 지운 휴대폰 등)와 중복 확인 조회 실패는 경보만 가고 1시간 창은 그대로다
- [ ] (2026-10-08) 첫 발송에 **일시 실패**(FCM·SMTP·웹훅 5xx·DNS 흔들림 등)나 **조회 실패**(DB — 보호자 연락처·연결·등록 휴대폰, 등록 휴대폰 경로 8초 초과 포함)가 있었으면 중복 방지 기록을 남기지 않는다 → 같은 응급이 **60초 뒤부터** 다시 감지되면 모든 경로로 다시 보내, **이미 받은 보호자도 한 번 더 받는다**(조용함보다 중복 — 빠진 사본의 받는 사람에게도 가야 한다). 그때는 운영자 경보("…일부 경로 일시 실패" · "…위급 알림 발송 실패" · "…조회 실패(DB)" · "…발송 시간 초과(FCM)")가 함께 온다 — 중복 알림을 결함으로 적기 전에 그 경보부터 확인
- [ ] 보호자 화면(위급 이력)에 **응급 발화만** 노출, **일상 대화 원문은 비공개**
- [ ] 일상 발화(`오늘 날씨 좋네`)로는 **알림 안 감**(오탐 없음)

## 7. 지연·안정성
- [ ] 응급 발화 → 알림 도착까지 **시간 측정**(목표 10초 이내)
- [ ] 여러 번 반복해도 안정적으로 도착 (토픽 fan-out 지연 편차 확인)
